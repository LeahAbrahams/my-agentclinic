# מחסנית טכנולוגיות וכללי פיתוח

## כללי פיתוח

1. קוד TypeScript ייבדק עם `strict: true`; אין לעקוף שגיאות טיפוסים באמצעות
   טיפוסים עוקפים או `any` ללא הצדקה מתועדת.
2. כל תלות ישירה תוגדר בגרסה מדויקת, וקובץ Lock יישמר במאגר לאחר בחירת מנהל
   החבילות.
3. שינויי סכמת SQLite ייעשו באמצעות מיגרציות SQL גרסאיות; אין לשנות סכמות
   באופן ידני בסביבת ריצה.
4. פיצ'ר יתחיל ממפרט עם דרישות ותנאי קבלה; מימוש ייחשב שלם רק לאחר בדיקת
   תנאי הקבלה הרלוונטיים.
5. תצוגת האפליקציה תהיה בעברית וב-RTL, ותיבדק ברוחבים צרים ורחבים לפני הכרזה
   על השלמת ממשק.
6. נכסים וסגנונות הנדרשים לפעולת האפליקציה יסופקו מקומית. אין להסתמך על CDN,
   גופנים מרוחקים, API ציבורי או שירות חיצוני כדי לטעון תוכן חיוני.
7. אין להציג אבחון רפואי או טיפול; תוכן כושר ומזון יהיה כללי, אלא אם הוגדר
   ונבדק אחרת במפרט מאושר.

## מדיניות בדיקות

- לכל התנהגות חדשה יוגדרו בדיקות אוטומטיות בהתאם לשכבה: בדיקות יחידה ללוגיקה,
  ובדיקות אינטגרציה לנתיבי שרת/מסד נתונים לפי הצורך.
- לפני סיום משימה יש להריץ בדיקות, בדיקת TypeScript ובדיקת Build/הרצה כפי
  שיוגדרו ב-`package.json`; התוצאות יירשמו ב-`TASKS.md`.
- יש לבדוק באופן ידני מסלולים מרכזיים בדפדפן כאשר הפיצ'ר כולל ממשק.
- בדיקת נגישות, RTL ורספונסיביות תיכלל באימות של פיצ'רים עם ממשק.
- מדיניות זו היא בסיס מוצע; Runner, פקודות, כיסוי ונתוני בדיקה ייקבעו לאחר
  יצירת השלד ולפני מימוש פיצ'רים.
