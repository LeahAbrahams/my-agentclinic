# מחסנית טכנולוגיות וכללי פיתוח

| רכיב | בחירה / גרסה | מצב והערות |
|---|---|---|
| סביבת ריצה | Node.js | נבדקה `24.13.0`; הוגדר טווח פרויקט `>=24.13.0 <25` |
| שפה | TypeScript `6.0.3` | ננעלה כתלות פיתוח בפרויקט |
| הרצה בפיתוח | tsx `4.23.15` | ננעלה כתלות פיתוח |
| הגדרות Node.js | `@types/node` `24.19.2` | ננעלה כתלות פיתוח |

| בדיקות | Vitest `4.1.12` | ננעל כתלות פיתוח; כללי הבדיקה ופקודת `npm test` מפורטים בהמשך |

## כללי פיתוח

1. קוד TypeScript ייבדק עם `strict: true`; אין לעקוף שגיאות טיפוסים באמצעות
   טיפוסים עוקפים או `any` ללא הצדקה מתועדת.
2. כל תלות ישירה תוגדר בגרסה מדויקת, וקובץ Lock יישמר במאגר לאחר בחירת מנהל
   החבילות.
3. שינויי סכמת SQLite ייעשו באמצעות מיגרציות SQL גרסאיות; אין לשנות סכמות
   באופן ידני בסביבת ריצה.
4. פיצ'ר יתחיל ממפרט עם דרישות ותנאי קבלה; מימוש ייחשב שלם רק לאחר בדיקת
   תנאי הקבלה הרלוונטיים.
5. תצוגת האפליקציה תהיה בעברית וב-RTL, ותיבדק ברוחבים צרים ורחבים לפני הכרזה
   על השלמת ממשק.
6. נכסים וסגנונות הנדרשים לפעולת האפליקציה יסופקו מקומית. אין להסתמך על CDN,
   גופנים מרוחקים, API ציבורי או שירות חיצוני כדי לטעון תוכן חיוני.
7. אין להציג אבחון רפואי או טיפול; תוכן כושר ומזון יהיה כללי, אלא אם הוגדר
   ונבדק אחרת במפרט מאושר.

## מדיניות בדיקות

- Vitest `4.1.12` הוא ה-Runner האוטומטי של הפרויקט; `npm test` מריץ את
  הבדיקות פעם אחת ללא מצב Watch. בדיקות נתיבי Hono ישתמשו ב-`app.request` כשאין צורך
  בחיבור רשת.
- לכל התנהגות חדשה יוגדרו בדיקות אוטומטיות בהתאם לשכבה: בדיקות יחידה ללוגיקה
  ובדיקות אינטגרציה לנתיבי שרת/מסד נתונים לפי הצורך.
- לפני סיום שינוי יש להריץ `npm test`, `npm run typecheck` ו-`npm run build`.
  יש לתעד תוצאות ב-`TASKS.md`; כשל באחת מהפקודות מונע סימון השלמה.
- כאשר פיצ'ר כולל ממשק, יש לבדוק מסלולים מרכזיים בדפדפן, נגישות ו-RTL.
- כל ממשק חדש יהיה mobile-first וייבדק ברוחב צר וברוחב שולחני. פיצ'ר ללא UI,
  כגון Hello Hono, אינו מקבל CSS או בדיקת פריסה רק לצורך סימון המשימה.
