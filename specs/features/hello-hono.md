# מפרט פיצ'ר: Hello Hono

- **Branch**: `feature/hello-hono`
- **נוצר**: 2026-11-12
- **סטטוס**: אושרה למימוש; Commit מקומי לפני תחילת המימוש

## מטרת הפיצ'ר

להוסיף נקודת כניסה מקומית זעירה המבוססת על Hono, כדי לוודא שאפשר להפעיל שרת
TypeScript ולבדוק תגובת HTTP בפועל לפני בניית ממשק Agent Clinic.

## בסיס היקף

- **שיטת גילוי**: ראיון דרישות וסקירת שלד הפרויקט החדש.
- **פריטים קיימים שנסקרו**: אין נתיבי HTTP או ממשקי מוצר.
- **פריטים בתחום**: נתיב אחד בלבד — `GET /`.
- **מחוץ לתחום**: ממשק HTML, Header/Main/Footer, מסד SQLite, Pico CSS, אימות
  משתמשים, ניהול מתכונים, תכונות כושר, API נוסף ופריסה מרוחקת.

## תרחישי משתמש ובדיקות

### סיפור 1 — אימות שהשרת פועל (עדיפות P1)

כמפתחת או כמשתמשת, אני מפעילה את הפרויקט וניגשת לכתובת המקומית, כדי לראות
תגובה ברורה שמאשרת ש-Hono פועל.

**למה בעדיפות זו**: זהו שער ההפעלה הראשון והבסיס לפיצ'רים הבאים.

**בדיקה עצמאית**: הפעלת שרת הפיתוח ושליחת בקשת `GET` יחידה ל-`/`.

**תרחישי קבלה**:

1. **בהינתן** שהשרת הופעל בהצלחה, **כאשר** נשלחת בקשת `GET /`,
   **אז** מתקבל סטטוס `200` והגוף המדויק `Hello Hono!`.
2. **בהינתן** שהשרת מאזין בפורט ברירת המחדל, **כאשר** פותחים
   `http://localhost:3000/`, **אז** מתקבלת אותה תגובה.
3. **בהינתן** נתיב שאינו בתחום, **כאשר** נשלחת אליו בקשת `GET`,
   **אז** מתקבל סטטוס `404` ולא הודעת ההצלחה של `/`.
4. **בהינתן** שפורט `3000` תפוס, **כאשר** מפעילים את השרת,
   **אז** שגיאת ההפעלה מוצגת והשרת אינו עובר לפורט אחר בשקט.

## דרישות

### דרישות פונקציונליות

- **REQ-001**: השרת MUST לטפל בבקשת `GET /`.
- **REQ-002**: הצלחה ב-`GET /` MUST להחזיר סטטוס HTTP `200`.
- **REQ-003**: גוף התגובה MUST להיות בדיוק `Hello Hono!` ולהיות מסוג
  `text/plain`; אין להוסיף HTML או JSON.
- **REQ-004**: כל נתיב שלא הוגדר MUST להישאר לא זמין ולהחזיר `404`.

### דרישות טכניות ולא-פונקציונליות

- **REQ-005**: המימוש MUST להשתמש ב-Hono `4.13.18` ובמתאם Node
  `@hono/node-server` `2.1.8`; הגרסאות המדויקות יאוחסנו ב-`package.json`
  וב-`package-lock.json`.
- **REQ-006**: סביבת הריצה MUST להיות Node.js בטווח הפרויקט
  `>=24.13.0 <25`, והקוד MUST לעבור TypeScript במצב `strict: true`.
- **REQ-007**: השרת MUST להאזין ב-localhost בפורט `3000` כברירת מחדל.
  לא ייבחר פורט אחר בשקט אם הפורט תפוס; שגיאת ההפעלה תוצג באופן גלוי.
- **REQ-008**: התנהגות הנתיב MUST להיות ניתנת לבדיקה אוטומטית בלי לפתוח
  חיבור רשת, ובדיקת עשן נוספת MUST לאמת הפעלה ותגובה דרך HTTP מקומי.
- **REQ-009**: הפיצ'ר MUST לפעול מקומית ללא CDN, שירות חיצוני או מסד נתונים.
- **REQ-010**: לא ייכללו HTML, CSS, נתוני משתמש או התנהגות מוצרית מעבר
  לדרישות המפורטות כאן.

## הנחות והחלטות

- המשתמשת אישרה שימוש בשיקול דעת לגבי הנתיב, תוכן התגובה, הפורט והממשק;
  נבחרו `GET /`, טקסט פשוט, פורט `3000` וללא HTML.
- אין צורך ב-SQLite או במיגרציות עבור הודעת פתיחה זו.
- אפשר להשתמש ב-`tsx` וב-Node `node:test` שכבר ננעלו בשלד, ללא הוספת Runner
  נוסף. פקודת הבדיקה תוגדר בזמן המימוש.
- דיוקי גרסאות Hono ומתאם Node נבדקו ברישום npm ביום יצירת המפרט; אין עדיין
  התקנה או בדיקת תאימות, והן ייעשו לאחר אישור המפרט.

## תוכנית עבודה ומשימות

### קבוצת משימות 1 — תלות והגדרות

1. להוסיף את `hono@4.13.18` ואת `@hono/node-server@2.1.8` כתלויות מדויקות.
2. לעדכן Lockfile ולהריץ `npm ci` כדי לוודא התקנה שחוזרת על עצמה.
3. להגדיר פקודות פיתוח, Build, בדיקה והפעלה סופית ב-`package.json`.

### קבוצת משימות 2 — שרת ונתיב

1. ליצור אפליקציית Hono עם `GET /` בלבד.
2. להגדיר תגובת טקסט פשוט מדויקת וסטטוס `200`.
3. להפעיל דרך Node adapter ב-localhost:3000 ולוודא ששגיאת Bind אינה נבלעת.
4. לא להוסיף עמוד, נתיב בריאות או מסד נתונים במסגרת פיצ'ר זה.

### קבוצת משימות 3 — בדיקות ותיעוד

1. לכתוב בדיקות Node מובנות להתנהגות `GET /` ולנתיב לא קיים.
2. להריץ בדיקת טיפוסים, Build ובדיקות אוטומטיות.
3. להפעיל את השרת ולבדוק את התגובה ב-HTTP מקומי.
4. לעדכן את README ואת `TASKS.md` רק לאחר אימות התוצאות.
